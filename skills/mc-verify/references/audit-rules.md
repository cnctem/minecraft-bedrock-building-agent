# 体检判据与修法（几何 / 结构 / 占地）

本手册的思路: **建完立刻用机器判据体检, 把结论当成“下一次设计必须避免的清单”**。
判据分三层, 每层都能落到具体的“哪个参数写错了”:

| 层 | 抓什么 | 典型根因 |
|---|---|---|
| 几何体（按 Y 层统计） | Y 层尖峰 / 等截面柱 / 飘空薄板 / 散点层 / 结构重叠 | 高度参数写错位、把带高度的函数参数位写反 |
| 结构体（连通与外壳） | 门窗悬空 / 结构碎裂 / 外壳缺口 | 门窗没贴墙、某段构件写到错误 XZ、围合循环少跑一段 |
| 占地（构件平面） | 构件 XZ 相交 | 摆放前没算占地，建筑压到城墙/互相穿插 |

## 1. 几何体检（BuildGeometryAudit）

统计口径: 只算实体方块(排除 air)，按 `y` 层累计“方块数 + 该层 XZ 包围盒”，少于 400 块不体检。

| 判据 | 触发条件 | 说明 | 怎么改 |
|---|---|---|---|
| **Y 层尖峰** | 某层方块数 ≥1500 且 ≥ 层中位数 ×3 | 疑似某构件的「高度参数」写错，整片被铺到意外标高 | 对照该函数签名，确认高度参数在第几位；先 `render_build(views=["front","iso"])` 看是不是整层浮板 |
| **等截面柱** | 连续 ≥8 层的「方块数 + XZ 占地」逐字相同 | 把带高度参数的函数参数位写错，生成了一根上下等粗的柱子 | 塔/烟囱/柱必须收分：`tapered_cylinder` 或逐层内缩；检查高度参数是否被当成了半径 |
| **飘空薄板** | 单层覆盖 ≥90% 占地，但上下相邻层方块数 ≤ max(4, 本层/50) | 铺装类构件的高度参数错位（整片悬在半空） | 铺装/地毯/天花的高度应贴住目标层；`gardenPath`/`carpetArea`/`arbor`/`lanternCeiling` 等 7 个函数的 **y 在最后一个参数位** |
| **散点层** | 某层 ≥500 块，却只覆盖 <5% 的建筑占地 | 装饰类构件被撒到不该在的高度 | 装饰要贴墙/贴地；检查装饰函数的 y 与主体层高是否对齐 |
| **结构重叠** | 两个构件的 XZ 占地相交 ≥4 列 | 后写的方块会覆盖先写的，外观就是“两个构件叠在一起” | 摆放前算两个矩形是否相交；**有意重叠**只有: 城墙 × 角塔/穹顶/城门楼、穹顶 × 同尺寸棱柱 |

## 2. 结构体检（BuildStructureAudit）

| 判据 | 触发条件 | 说明 | 怎么改 |
|---|---|---|---|
| **门窗悬空** | 门/活板门/栅栏门/玻璃板类方块，上下左右前后都没有实体墙 | 门窗被写到半空或轮廓之外 | 先有墙再开窗；窗的 `(cu, cw)` 要落在墙所在的平面上，`v` 落在该段墙的层高内 |
| **结构碎裂** | 最大连通分量 <80%，且 3~8 格的小碎块 ≥3 处（大建筑用 48 格粗网格: 主体 <35% 且分量 ≥5） | 某段构件被写到很远的 XZ，或某片外围建筑与主体完全脱开 | 检查循环里的 x/z 是否用了正确变量；分块施工时确认 `origin` 与局部坐标一致 |
| **外壳缺口** | 某层外圈占用 ≥60%，最长连续缺口 ≥5 格，且内部填充 ≤60%（说明这层本来是“围合”） | 围墙/房壳的循环少画了一段 | 检查这层围合 for 循环的起止边界与步长（`range(a, b)` 是否漏掉末位） |

## 3. 占地契约（BuildFootprints）

本手册对每个“整栋风格函数”都记了**最小占地**，并在放置时检查相交。本项目对应 `api.lib` 的整栋模板：

- 模板的 `(u, w)` 是占地的**最小角**，向 `+u / +w` 展开 `size` 格（**不是以中心**）；
  摆放前先算两个矩形是否相交，相邻建筑至少留 2 格净距。
- 城墙（`rampart`）的厚度**以给定线为中心向两侧展开**：占
  `[线 - thickness/2, 线 - thickness/2 + thickness - 1]`。
  副建筑/道路/广场必须完全落在围墙**内表面**以内（留 ≥2 格），否则城墙会把建筑切掉一块。
- 角塔/穹顶/城门楼压在墙上是**有意重叠**；其余构件不许压墙。
- 城门洞要通，**城门楼必须写在城墙之后**（后写覆盖先写），否则通道被先写的城墙焊死。
- 整栋模板单体方块数参考: 小屋 ≈400 / 酒馆 ≈800 / 教堂 ≈1800 / 主楼 ≈2500 /
  城门 ≈600 / 风车 ≈500 / 摊位 ≈120 / 灯塔 ≈900。用「目标方块数 ÷ 单体方块数」估数量。

## 4. 体检结论要回灌

本手册把上一次的体检结论**作为下一轮的提示**（“请不要重犯”），因为同一类参数错位会反复出现。
本项目的对应做法:

1. `build_preview` 的 `symmetry` / 悬空检查 / `[程序输出]` 先看一遍；
2. `build_commit` 的 `verify`（holes/wrong）不为 0 就写补丁程序，而不是重做整栋；
3. 出错后**把根因记进 `memory.md` 或本次任务备注**（例如“gardenPath 的 y 在最后一位”），
   避免同一会话里反复踩同一个坑。

## 5. 判据 → 本项目工具的对照

| 原判据 | 本项目怎么查 |
|---|---|
| Y 层尖峰 / 飘空薄板 / 散点层 | `render_build(views=["front","iso"])` 看立面与立体；`get_slice(axis="y", level=…)` 逐层看 |
| 等截面柱 | `render_build` 的 front/iso；或 `get_slice(axis="x"/"z")` 看侧剖面 |
| 结构重叠 | `build_preview` 的差异统计（覆盖格数异常高）+ `render_build` 的 top 视图 |
| 门窗悬空 | `build_preview(scan=[...])` 的悬空检查（门窗类方块靠墙不算悬空，仍要肉眼确认贴墙） |
| 结构碎裂 / 外壳缺口 | `get_slice` 逐层看外圈是否闭合；`inspect_region(filter=…)` 的 mismatch 样本 |
| 占地相交 | 摆放前手算矩形；或 `get_heightmap`/`inspect_region` 先摸清已有建筑范围 |
