# 分层体块法（先画平面，再写程序）

本手册在中小型建筑上会让模型先输出**逐层平面字符网格**，再据此编写 Python 建造程序；大型建筑则直接写代码。
这套网格法的价值不在格式，而在**强制你先定“每层外轮廓怎么收”**——屋顶收分、退台、外墙闭合
这三件事，只有在逐层平面上才看得清。

本项目没有 `<layers>` 解析器，等价做法是：

> 先用消息/草稿画 3~5 层关键平面（地面层 / 标准层 / 收分层 / 屋顶层），确认轮廓与门窗位置，
> 再用 `mc-build` 写程序；每层用 `api.fill/box` 或 `api.lib` 构件落地。

## 1. 网格语法（画草稿时照这个来）

```
图例(legend):
.  = 不放置（这里什么都没有）
-  = 显式挖空（真的把已有方块挖掉 → air）
S  = stonebrick
W  = oak_planks
G  = glass_pane
L  = dark_oak_log
R  = oak_stairs（朝向另记）
层 y=0
..LLLLLLLL..
..L......L..
..L..GG..L..
..LLLLLLLL..
层 y=1 重复 4
..W......W..
..W......W..
层 y=5
....SSSS....
```

规则（每条都影响“能不能建出来”）：

1. **图例写在所有层之前**，一行一个字符 → 方块名，用 ` = ` 或 `: ` 分隔；图例里没定义的字符 = 坏格。
2. `.`（或空格）= **不放置**；`-`（或图例里映射成 air 的字符）= **显式挖空**。
   要在墙上开洞、或挖掉地形，必须用挖空；只写 `.` 是“那里不盖”，不是“把它挖掉”。
3. 方块名必须是真实完整名字，可带状态（如 `oak_stairs[direction=2]`）；写错的格子会被跳过 → 留洞。
4. `层 y=N`：N 从 0 开始（0 = 脚底层），向上递增；`层 y=3 重复 5` 表示 y=3..7 各放一遍
   （标准层/塔身必备）。
5. 每层是若干行**等长**字符：一行 = 一个 Z（第一行在最北，向下每行 +1）；
   一行里第 c 个字符 = 一个 X（第 0 个在最西，向右 +1）。
6. **单层 ≤96×96，总层数 ≤128**；只写真的有方块的位置。
7. 层从下往上写，重要的层写在前面（地面 → 主体 → 屋顶）；超出上限时靠后的层整层丢弃。
8. **每层外墙要闭合**（四面都画上），否则墙会漏风漏雨。

## 2. 输出前自检

1. 网格里每个字符都在图例里定义过？图例里的字符至少用过一次？
2. 每层每行是否等长？
3. 方块名拼写是否与 `find_items` / `data/raw_ids.txt` 一致？
4. 每层外墙是否闭合（四面都有）？
5. 屋顶是否逐层收分（越往上外轮廓越小），而不是到顶还是同样大的轮廓？
6. 是否 ≥3 种材质（主材/辅材/点缀），且屋顶材质与墙体不同？
7. 单层 ≤96×96、总层数 ≤128？层号从 0 开始连续？
8. 门窗位置是否用挖空字符（air）开出来，而不是只留 `.`？

## 3. 从网格到程序（本项目）

```python
# 地面层(y=0)：外墙闭合 + 门口挖空
api.fill((0, 0, 0), (W - 1, 0, D - 1), "stonebrick")
api.fill((W // 2 - 1, 0, 0), (W // 2, 0, 0), "air")     # 门洞：显式 air

# 标准层(y=1..4)：四面墙 + 窗洞
for v in range(1, 5):
    api.fill((0, v, 0), (W - 1, v, 0), "oak_planks")
    api.fill((0, v, D - 1), (W - 1, v, D - 1), "oak_planks")
    api.fill((0, v, 0), (0, v, D - 1), "oak_planks")
    api.fill((W - 1, v, 0), (W - 1, v, D - 1), "oak_planks")
api.fill((W // 2 - 1, 2, 0), (W // 2, 3, 0), "glass_pane")  # 窗（替换墙格）

# 屋顶层：逐层内缩（网格里每上一层外轮廓缩 1 格）
api.lib.chinese_roof(-1, -1, W, D, 5, max(3, D // 2), "硬山",
                     "deepslate_tiles", "polished_blackstone")
```

- 网格里的 `.` → **不写**（KEEP 语义，程序没提到的格子不写也不删）；
- 网格里的 `-` → `api.fill(..., "air")`（**必须显式写**，否则挖不动）；
- 网格里的 `repeat N` → `for v in range(...)`；
- 网格里的轮廓收分 → 交给 `chinese_roof` / `api.roof(style=..., hollow=...)`，
  不要手写每层内缩（容易漏掉某一边）。

## 4. 什么时候用网格、什么时候直接写程序

| 情况 | 建议 |
|---|---|
| 中小型（≤1 万方块）、形状讲究（塔、亭、住宅、门楼） | 先画 3~5 层网格草稿，再写程序 |
| 大型/超大型（>1 万方块）、建筑群 | 直接写程序 + 分区；网格只画“标准单元”一张 |
| 纯装饰/铺装/植被 | 不用网格，直接调 `api.lib` 的对应函数 |

本手册的经验：**网格法的收益在“收分与闭合”，不在“逐格画满”**。把关键层画对，
其余交给循环和构件函数，比画 30 层网格更省时间。
