# 施工规划（场地 → 规模 → 体块 → 分区）

> 这一本的判据来自原 Java 建筑模组的 `BuildingPlanner`、`BuildScale`、
> `LayeredBuildGuide`、`ImageBuildGuide` 四个类：它们把“开工前该算什么”写成了硬规则。
> 具体构件与风格见 `mc-architecture`，写程序见 `mc-build`，验收见 `mc-verify`。

## 0. 三句话

1. **先算地**：高差 >4 格、有岩浆、或大面积障碍 → 换地方或改台地，不要硬建。
2. **先定量**：中小型 1 千~1 万 / 大型 1 万~50 万 / 超大型 50 万~160 万方块；
   档位决定“分几次 preview”，不是“一次提交多少”。
3. **先定体块**：关键 3~5 层的平面轮廓（收分、外墙闭合、门窗位置）定下来，再写程序。

## 1. 场地分析（`references/site-analysis.md`）

```text
get_player_position          定中心与朝向
get_heightmap(x1,z1,x2,z2)   高差 / 平整度 / 顶面类型
get_slice(axis="y", level=…) 看已有建筑占地与材质
inspect_region(…)            障碍与占用
find_blocks("water"/"lava")  水域 / 岩浆范围
```

结论只有三种：**直接建** / **先做台基或台地** / **换地方**。判据：

| 高差 | 结论 |
|---|---|
| ≤1 | 平坦，直接建 |
| 2~4 | 做台基 / 挡土墙，不挖不填 |
| >4 | 改台地（每层 1:2 坡道或 3~5 级台阶），或嵌进山体 |
| 有岩浆 | 不建议在此建造 |

## 2. 规模档位（`references/scale-tiers.md`）

| 档位 | 目标方块数 | 典型对象 | 本项目做法 |
|---|---|---|---|
| 中小型 | 1,000 ~ 10,000 | 民居、商铺、塔、亭、小教堂 | 1~2 次 preview 完成 |
| 大型 | 10,000 ~ 500,000 | 城堡、修道院、大教堂、宫殿 | 按模块（地基/墙身/屋顶/内部/环境）分 4~6 段 |
| 超大型 | 500,000 ~ 1,600,000 | 城镇、建筑群、大型园林 | 先样板 2~3 栋 → 循环变体 → 分区推进 |

单次提交上限是 65536 格；档位只是整栋/整片的目标，**永远分段提交**。

## 3. 分层体块法（`references/blockout-layers.md`）

先画地面层 / 标准层 / 收分层 / 屋顶层四张平面（字符网格），确认三件事：
**每层外墙闭合、门窗位置、屋顶逐层收分**。然后把网格翻成程序：

- `.` → 不写（KEEP）
- `-` → `api.fill(..., "air")`（显式挖空）
- `重复 N` → `for v in range(...)`
- 轮廓收分 → 交给 `api.lib.chinese_roof` / `api.roof(style=..., hollow=...)`

## 4. 照参考图建（`references/reference-image.md`）

- 体量：**4×4 像素 ≈ 1 方块**；宽高按图定，不按档位放大。
- 顺序：剪影一致 → 主色分区（≤5 色）→ 关键特征 → 纵深分层（≥3 个厚度档）。
- 颜色→方块有固定映射表（白→`white_concrete`、中灰→`stonebrick`、透明→`glass` …）。
- 用 `render_build(views=["front"])` 与图并排对比，再提交。

## 5. 分区与断点续建

**分区**（超大型必做）：

1. 按 30~50 格划功能区（主殿 / 广场 / 街道 / 庭院 / 园林 / 居住 / 市场）；
2. **每个区主体完成后立即装饰该区**，再建下一区（原模组经验：先建完再统一装饰会漏）；
3. 每区独立 `build_preview` → `build_commit`，坏了只回滚这一区。

**断点续建**（任务跨会话/被压缩后）：

1. `logs/sessions/*.jsonl` 里找 `build_preview` 的 program 与 `origin/facing`；
2. 重新 preview 一次（KEEP 语义保证已建部分 `noop`，不会重复覆盖）；
3. 只补 `verify.holes/wrong` 列出的格子，或继续下一个模块；
4. 把“已完成/待建”写清楚，避免重复施工。

## 6. 本项目落地清单

- [ ] 场地结论（直接建 / 台基 / 换地方）已给出
- [ ] 档位与目标方块数已估，并告诉玩家“分几段”
- [ ] 关键层平面草稿已定（外墙闭合、屋顶收分、门窗位置）
- [ ] 若是照图建：剪影已核对、主色 ≤5、纵深 ≥3 档
- [ ] 每段施工都走 `build_preview` → `render_build` → `build_commit` → `verify`
