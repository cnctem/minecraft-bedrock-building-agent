# 会话、上下文与模型

本文说明主会话的生命周期、前缀缓存、清空/压缩/恢复，以及会话级模型选择。
一次性对话和静默消息见[运行模式与对话策略](modes.md)，控制词总表见[运维与控制面](operations.md)。

## 1. 会话生命周期

- 解析 BDS 的 `Player connected/disconnected` 维护在线人数。
- 在线人数 **0→1** 时完整初始化新会话；旧会话有实际对话则落盘到 `logs/sessions/`。
- 全员离开（→0）**不结束会话**，正在执行的任务可以跨离线期继续。
- 如果 0→1 时任务仍在运行：不初始化，也不排队等待初始化，只提示任务仍在运行以及可用的停止/压缩/清空控制词；
  当前会话与上下文继续保留。
- 新会话开始时注入长期记忆、技能清单和当前模式等系统注记。只有系统注记、没有实际对话的空会话不落盘。
- 一次性对话使用独立 `OneShotContext`，不影响上述主会话生命周期。

“清空”与 0→1 使用同一套完整初始化，但清空还必须满足空闲条件，见下文。

## 2. Append-only 与前缀缓存

平时上下文**只追加、不修改、不重排、不做滑动窗口**：

- 全局 system prompt 保持常量。
- 长期记忆和当前模式不写进全局 system prompt，而是作为 `role=system` 注记追加在消息日志里。
- 会话开始注入一条记忆注记；`update_memory` 后追加最新记忆注记；`set_mode` 后在工具响应之后追加模式注记。
- 每轮请求前缀保持稳定，以命中模型供应商的前缀缓存；`logs/bot.log` 中的缓存统计可用于观察效果。
- 服务器内普通聊天都进入上下文，是否回应由模型判断；`0 ...` 静默消息和硬编码控制词除外。
- 发送前 `_sanitize` 会修复破损的工具配对：删除孤儿 tool，丢弃配不全的 tool_calls，避免后续请求持续 HTTP 400。

`reasoning_content` 只进入 `logs/bot.log`，不作为可见正文；是否随 assistant 工具调用回传由模型档案决定。

## 3. 任务中写入消息的安全点

任务运行中收到的新玩家消息只在工具往返闭合后注入，保证 `assistant(tool_calls)` 与对应 `tool` 严格成对。
软停止也在安全点生效；被中止的调用会补上“(已中止)”或“(已到安全点停止)”响应，不把半段工具序列留给下一次请求。
控制词本身不进上下文，避免多线程追加破坏配对。插话后的调度细节见[运行模式与对话策略](modes.md#7-任务中插话)。

## 4. 清空与模型切换

### 4.1 清空的并发规则

任何玩家单独发送 **`清空`**（完全匹配）会结束当前会话并完整初始化新会话：旧会话落盘、模式复位 normal、
生成新 session id、重新注入长期记忆。

**只有空闲时才能清空。** `busy = agent_busy or 有待处理消息 or 智能压缩运行中`；busy 时：

- 不自动中止任务；
- 不清上下文；
- 不换模型；
- 回复提示，要求先“停止”或“强制停止”。

压缩、智能压缩、备份等需要空闲的控制面采用同一基本原则。超预算时的自动清空是程序内部兜底，不等玩家再发控制词。

### 4.2 模型是会话级状态

会话内不能直接换模型，否则缓存、思考链字段和供应商参数口径会混用。模型通过“清空”系列控制词在新会话开始时选择，
必须完全匹配；`清空 k`、`清空x` 等未配置写法都是普通聊天。

当前示例配置中的档案：

| 触发词 | 别名与模型 | 状态/说明 |
|---|---|---|
| `清空` | `flash` / DeepSeek Flash（`deepseek-flash`） | 默认模型；进服自动开新会话和一次性对话也用它 |
| `清空k` | `kimi` / Kimi K3.1 Pro（`k3.1-pro`） | 使用 Kimi Code Base URL；示例窗口主动限为 262144 |
| `清空g` | `gpt` / GPT-6 Astra（`gpt-6-astra`） | 示例中 `enabled=false`，未接通；发送后不清空、不换模型 |

实际可用模型以本地 `config.json` 为准，不应根据示例名称假定线上已开通。每个档案可配置：

- `label` / `trigger` / `api_base` / `api_key` / `model` / `enabled`；
- `context_window_tokens` / `max_output_tokens` / `api_timeout_sec`；
- `effort_param` / `effort_map` / `reasoning_content` / `temperature`。

缺 Base URL、key 或模型名即视为未接通。默认 flash 的身份字段继承顶层配置，老配置没有 `models` 也可运行；
其他模型必须自行写全身份字段，避免误继承别家的 key 或 Base URL。

### 4.3 思考参数差异

模式只产生 low/high/max 三档逻辑强度，由模型档案映射为真实字段：

- DeepSeek 示例使用顶层 `effort`；
- Kimi 示例使用 `reasoning_effort`，并固定 `temperature=1`；
- `effort_map` 某档映射为 `null` 时，该档不发送强度字段；
- `reasoning_content=false` 表示历史 assistant 消息不回传思考链，可节省输入 token。

清空回执会点名新模型。一次性对话永远使用 flash，不受主会话模型影响。

## 5. 上下文预算与占用提醒

输入预算按以下口径估算：

```text
输入预算 = 当前模型上下文窗口 − 本轮输出上限 − context_safety_tokens
```

token 数是基于消息 JSON 字符的保守估算；图片按固定估算值计，不把 base64 字符串当文本 token。

- 上下文占用跨过裸模型窗口的 70% / 80% / 90% 时，分别用 `[系统]` 提醒一次。
- 提醒会说明自动智能压缩阈值，以及手动“智能压缩”和“压缩”的区别；只提醒，不改变任务。
- 到**输入预算**的 `smart_compact_auto_pct`（默认 95%）时自动智能压缩。
- 超过输入预算时进入普通压缩；压缩后仍超预算才完整清空。
- 每次请求开始和工具轮次安全点都会检查。
- 压缩、清空、新会话后提醒档位复位。

自动智能压缩用输入预算而不是裸窗口，是因为输出预留可能占较大比例；若按裸窗口计算，可能尚未触发智能压缩就先撞上硬预算。

## 6. 普通压缩：只保留对话

玩家单独发送 **`压缩`**，或程序在超预算时触发，会有意重写上下文。busy 时手动压缩无效，不自动停止任务；
一次性对话不压缩。

### 6.1 保留与移除

**保留：**

- 全部玩家消息；
- 维克托实际发送的游戏内发言：直接 `send_chat_message`，以及 ptc 内嵌的发言；
- 保留调用所必需的 assistant(tool_calls) 与 tool 响应，配对不全则整条丢弃。

ptc 会被重写为只含发言子调用，结果也只保留对应行并重新编号。

**移除：**

- 其他工具调用和结果；
- assistant 普通正文与思考内容；
- 旧系统注记；
- 无法配对的工具消息。

### 6.2 新会话结构

旧会话写入 `logs/sessions/compact-YYYYmmdd-HHMMSS-s<id>.jsonl`，新会话依次装入：

1. 长期记忆注记；
2. 技能清单注记；
3. 当前模式注记；
4. 保留下来的对话；
5. 压缩前最后一次建造程序（若有）；
6. `# 上下文已压缩` 注记。

模式、常加载区域和在线玩家名单不变；已加载技能集合清空，需要时重新 `use_skill`。
普通压缩是有损重写，会打破此前前缀缓存；新前缀从下一次请求起重新稳定。

`compact-*.jsonl` 仅供排障，不参与“恢复会话”或 `restart.sh` 自动恢复；它们只认 `session-*.jsonl`。

### 6.3 建造程序的特例

建造源码只存在于工具调用参数里，普通压缩本来会全部删除。两种压缩都会额外保留**最后一次**建造程序：
源码、origin/facing/name/scan/symmetry 等参数和该次结果摘要。

更早模块的源码无法恢复，只能按摘要、尺寸和坐标重写。压缩注记要求模型不要凭记忆假设现场已建状态，
应通过 `build_status`、`inspect_region`、`get_slice` 重新确认。

## 7. 智能压缩：模型工作摘要

**`智能压缩`** 类似 coding agent 的 `/compact`：先让模型整理工作摘要，再重建会话，保留比“谁说了什么”更多执行信息。

### 7.1 摘要输入与请求

- `Session.transcript()` 生成纯文本：玩家消息、游戏内发言、工具名与参数前段、工具结果前段；去掉 system 注记与思考链。
- 超过 `smart_compact_input_chars`（默认 40000）时保留开头原始需求与结尾当前进度，并明确标注中间省略字符数。
- `prompts.SMART_COMPACT_PROMPT` 要求分节整理：玩家与称呼、正在做的事、建造进度、失败与注意、承诺与待办、关键信息。
- 建造参数必须写全；未完成事项不能写成已完成。
- 摘要请求不带工具，使用 low 强度，输出上限 `smart_compact_max_tokens`（默认 2048）。

### 7.2 新会话结构

```text
长期记忆 / 技能清单 / 当前模式
→ # 压缩前的工作摘要
→ 最近 smart_compact_keep_recent 条消息的普通压缩对话（默认 8）
→ # 压缩前最后一次建造程序（若有）
→ # 上下文已智能压缩
```

### 7.3 失败与并发

- 摘要报错、超时、为空或被强制停止时，原上下文完全不变，只回系统提示。
- 自动触发失败后，本会话不再自动重试，避免每轮重复计费；手动“智能压缩”仍可使用。
- 手动触发要求空闲，与清空相同。
- 摘要在后台线程执行，期间 `_smart_compact_running=true`：新消息只排队，清空/普通压缩/备份/恢复等空闲控制词被拒绝，
  `logs/agent.state` 也报告 busy。
- “强制停止”可以中止摘要；结束后无论成败都会复位状态并唤醒 worker。

## 8. 恢复会话

任何玩家单独发送 **`恢复会话`**，程序选取最近一个含实际对话的 `logs/sessions/session-*.jsonl` 并灌回当前上下文。
任务运行或有待处理消息时拒绝恢复。

- 默认按首行 `_meta.model` 恢复原模型；老文件没有该字段则使用 flash。
- 从最后一条 `# 当前模式: ...` 注记推断并恢复模式。
- 技能清单若在落盘后变化，只在末尾追加最新清单，不重写旧前缀。
- 追加“历史工具已经执行过，不要重跑”的恢复注记，避免模型重复施工或重复转发。
- 从历史恢复最近对话对象，并以文件 mtime 近似发言时间。
- 按目标模型补齐或剥除 `reasoning_content`，避免不同供应商历史混用导致 400。

### 8.1 `恢复会话d`

**`恢复会话d`** 做同样的恢复，但忽略原模型，强制使用默认 flash。适合原模型欠费、限流或希望降低成本时继续旧对话。
从 Kimi 历史切到 DeepSeek 时会补空思考字段，反向则剥除不需要的字段。

### 8.2 平滑重启恢复

以 `VIKTOR_RESTORE=<session 文件路径>` 启动时，启动后静默灌回指定会话，不向玩家额外聊天。
`restart.sh` 会先 SIGTERM 优雅退出并落盘，再带最新 session 文件重启。也可手动：

```bash
python3 bot.py --resume logs/sessions/session-YYYYmmdd-HHMMSS-sN.jsonl
```

开发设备没有线上会话时不要执行生产恢复；应先确认路径属于哪个环境，详见根目录 `AGENTS.md`。

## 9. 会话历史工具与落盘的区别

`恢复会话` 是控制面操作，把最近 session 灌回当前上下文；`list_sessions` / `read_session` 是模型工具，
用于按需查看历史，不会自动恢复或修改当前会话。历史读取只展示玩家消息与游戏内发言，具体见[工具与并发](tools.md#5-会话历史)。
